# BatteryLife 电池详情接入（第一阶段）

本阶段把现有 BatteryLife 的单电池核心观察能力接入 BatteryLand。目录、划分和训练继续使用 BatteryLand 原有电池 UUID 与物理文件引用；详情页通过 UUID 打开，不接收客户端文件路径。

## 数据来源与口径

- 后端只读取 `BATTERYLAND_SOURCE_ROOTS` 中管理员配置的可信 `.pkl` 文件。原始文件只读，不复制，也不接受用户上传的 pickle。读取 pickle 需要后端环境安装 NumPy。
- 数据集原有寿命标签从同一数据根目录的 `Life labels/*.json` 读取，接口返回标签值和标签文件名。标签可能超过最后一个详细 Cycle；图中的虚线只标示标签位置，不生成容量记录。
- 容量轨迹每点取该圈有效放电容量的最大值；百分比以首个大于零的有效放电容量为基准。它不是各来源统一定义的 SOH。
- 接口使用文件中的 **0 起始记录序号**定位采样；同时返回原有 `cycle_number`。编号缺失时返回 `null`，编号重复时保留多条独立记录。页面按实际编号输入，重复编号默认打开第一条，并可逐条导航。
- 单圈图的横轴有有效时间戳时为相对首点的分钟数，否则为采样序号。超过约 1,800 点时均匀抽样，并保留首末点；容量摘要使用完整逐圈数组。
- 原始元数据与 BatteryLand 已登记元数据分别返回；本阶段不回写已登记字段。内存中只保留最近读取的一块原始电池和最多八份容量摘要，文件大小或修改时间变化时重新读取。

## 接口与页面

- `GET /api/v1/batteries/{id}/analysis`：原始测试条件、原有寿命标签、详细记录范围，以及每条记录的容量摘要。
- `GET /api/v1/batteries/{id}/cycles/{index}`：该条记录的实际编号、原有采样点数、展示抽样位置与电压、电流、充放电容量等信号。
- 电池目录的“查看曲线”在新标签打开 `/batteries/{id}`，原标签的筛选与选择保持在原处。详情页可通过点击或拖动容量曲线后松开、方向键、编号输入和前后记录按钮切换采样。
- 详情页先显示实际记录范围和容量曲线；完整原始测试条件可展开查看。协议的数值仅做显示精度整理，不改动源文件。
- 两个接口已写入 `specs/012-backend-service-protocol/contracts/core-openapi.json`，前端类型从该契约生成。

当前页面只覆盖核心详情。密集多圈、对照电池、dQ/dV、桑基图、群体轨迹、多电池曲线和 CSV 待复核流程按后续阶段迁入。总览中的物理文件数与经核实去重电池数将分开显示；此阶段不改变训练选择或既有数据集成员。

## 验证

先运行 `tests/integration/test_battery_detail.py`，再在 Linux 环境配置原始数据根目录，使用真实电池检查标签越界、缺号和重复 Cycle、采样抽样、页面选圈及现有划分入口。测试过程中应确认原始文件的大小与修改时间不变。
