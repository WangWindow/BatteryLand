# Feature Specification: 图形化数据集创建与划分

**Feature Branch**: `011-graphical-datasets`
**Created**: 2026-10-24
**Status**: Ready
**Input**: User request for graphical source and battery selection, practical dataset splitting, persisted data statistics, and a SQLite-only backend.

## User Scenarios & Testing

### User Story 1 - 选择来源并创建逻辑数据集 (Priority: P1)

用户从已登记的数据来源中选择一个开源数据集，可以使用该来源的全部已登记电池，也可以搜索、分页并挑选部分电池，然后为这一组数据命名并创建划分。

**Why this priority**: 当前数据来源和划分分散在两个页面与表单中。来源选择是创建可复用逻辑数据集的起点。

**Independent Test**: 使用两个已登记来源，分别选择全部电池和其中若干电池创建数据集；检查保存的成员与选择一致，且没有输入服务器路径或电池 UUID。

**Acceptance Scenarios**:

1. **Given** 有可用的数据来源，**When** 用户打开创建流程，**Then** 来源以可区分的色彩卡片呈现，并同时显示名称、电池数和可用状态。
2. **Given** 用户选中一个来源，**When** 用户选择“全部电池”，**Then** 当前来源中所有已登记电池进入待划分集合。
3. **Given** 用户选中一个来源，**When** 用户搜索并在多个分页中勾选电池，**Then** 已选电池跨页保留，页面清楚显示所选数量。
4. **Given** 来源尚未登记电池，**When** 用户打开创建流程，**Then** 系统提示先从来源目录登记文件，并禁用创建操作。

---

### User Story 2 - 可视化预览并保存数据划分 (Priority: P1)

用户通过手动分配或按比例随机分配训练集、验证集和测试集，查看服务端给出的确切成员数量，再保存为有名称和版本的逻辑数据集。编辑已有数据集时会创建新版本。

**Why this priority**: 划分决定训练数据边界，用户需要在提交前确认实际分配；划分历史必须能够被实验稳定引用。

**Independent Test**: 对固定的小型电池集合进行手动和随机划分，确认预览与保存成员相同；包含父子电池时确认其不会跨集合；编辑后读取旧版本与新版本并确认各自成员不变。

**Acceptance Scenarios**:

1. **Given** 用户选择了电池，**When** 用户设置训练、验证、测试比例，**Then** 三个比例合计必须为 100%，并可通过可视化比例条调整。
2. **Given** 用户使用随机或混合划分，**When** 用户调整比例或随机种子并请求预览，**Then** 页面显示由系统实际划分算法计算的三个分区成员数量。
3. **Given** 用户手动指定分区，**When** 同一电池家族的关联电池被分配到不同分区，**Then** 系统拒绝预览和保存，并说明相关电池不能跨分区。
4. **Given** 用户确认预览，**When** 用户保存划分，**Then** 后续读取到的三个分区成员与预览一致，且完整选中集合被保留。
5. **Given** 已有逻辑数据集，**When** 用户修改名称、成员或分区后保存，**Then** 系统新增版本，旧版本仍可读取和引用。

---

### User Story 3 - 为数据集版本保存可比较的统计摘要 (Priority: P2)

用户创建或更新逻辑数据集时，系统基于已登记的电池元数据保存整个逻辑数据集及各分区的统计摘要，以便后续差异比较不必重新扫描电池文件。

**Why this priority**: 统计信息是数据集比较的基础；与划分版本一起保存可避免元数据变化导致历史结果漂移。

**Independent Test**: 使用含分类属性、数值属性、缺失属性和自定义标量属性的电池集合创建数据集，读取该版本并确认全体及三个分区的统计摘要正确；重启数据库后结果保持一致。

**Acceptance Scenarios**:

1. **Given** 选中集合具有已登记元数据，**When** 用户创建逻辑数据集，**Then** 系统为全体成员及 train、val、test 分别保存样本数量和可用属性统计。
2. **Given** 某项属性在部分电池中缺失，**When** 读取统计摘要，**Then** 有效数量和缺失数量被分别记录，缺失不被当作零值。
3. **Given** 数值属性可用，**When** 读取统计摘要，**Then** 可见有效数、最小值、最大值和平均值；分类属性显示按值计数。
4. **Given** 自定义标量属性存在，**When** 保存统计摘要，**Then** 该属性也可被发现；非标量和无效数值不会伪装成有效样本。
5. **Given** 逻辑数据集已创建，**When** 用户更新并保存新版本，**Then** 新版本统计随成员更新，旧版本的成员和统计保持不变。

### Edge Cases

- 选择集合为空、来源不可用、来源没有已登记电池或搜索无结果。
- 全量选择的数据量大于当前页面；分页、搜索和来源筛选不得清除已选成员。
- 一个来源包含同名文件、重复登记文件或父子电池关系；以数据库电池身份为准，重复文件仍遵循来源导入规则。
- 比例为 0%、小样本比例导致一个或多个分区为空；准确展示数量，不自动伪造样本。
- 父子层级多于一层，或父关系存在循环、缺失引用；不允许保存不完整划分。
- 分类属性包含 null、空值、数字与字符串混合值；保持缺失与实际值的区别。
- 数值属性包含 NaN、正负无穷、布尔值或类型混杂；不得计入数值摘要。
- 请求预览时来源、成员或数据集版本已变化；返回明确冲突/校验错误，不保存过期预览。
- 统计计算或版本写入失败；划分版本与统计摘要不得出现部分提交。

## Requirements

### Functional Requirements

- **FR-001**: 用户 MUST 能从已登记来源创建逻辑数据集；每个首版逻辑数据集只包含一个来源中的电池。
- **FR-002**: 来源 MUST 以稳定且可读的视觉标识区分，同时显示来源名称和文本状态；颜色不能成为唯一辨识方式。
- **FR-003**: 用户 MUST 能选择来源中的全部已登记电池，或通过搜索和分页选择其中部分电池；跨页选择必须保留。
- **FR-004**: 用户 MUST 能选择手动、随机或混合划分，并为 train、val、test 设置数量比例；比例必须为 0 到 100%，总和为 100%。
- **FR-005**: 随机与混合划分 MUST 支持可复现的随机种子；用户看到的分区数量必须来自实际划分算法。
- **FR-006**: 划分 MUST 遵守相关电池家族不跨 train、val、test 的约束；手动划分冲突必须在保存前明确报告。
- **FR-007**: 用户 MUST 能在保存前看到三个分区的准确成员数量和所选总数；保存的成员与最近一次确认的预览一致。
- **FR-008**: 更新逻辑数据集 MUST 产生新版本；已有版本的成员和统计摘要必须保持不变。
- **FR-009**: 每个逻辑数据集版本 MUST 保存整个集合及 train、val、test 的统计摘要；摘要至少包括样本数、属性有效数/缺失数、分类值计数，以及数值字段的最小值、最大值和平均值。
- **FR-010**: 统计摘要 MUST 只依据电池记录已有的元数据计算，不得为生成统计而读取原始训练文件。
- **FR-011**: 自定义标量属性 MUST 能出现在统计摘要中；空值和不支持的非标量值不得冒充为有效数值。
- **FR-012**: 统计摘要 MUST 与其逻辑数据集版本一起持久化；保存失败时成员版本与摘要均不得部分生效。
- **FR-013**: 页面 MUST 提供简体中文和英文，覆盖来源选择、统计和所有状态，并使用可访问的控件标签。

### Key Entities

- **来源**: 已登记的数据集根别名及其可用状态；包含若干已登记电池。
- **电池**: 来源中的稳定身份、文件引用、可选父电池关系和扩展属性。
- **逻辑数据集版本**: 有名称的电池集合快照，包含 train、val、test 成员、划分方式、随机参数和独立版本号。
- **统计摘要**: 针对一个逻辑数据集版本及其全体/分区范围计算的结构化属性统计。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 用户可以不输入文件路径或 UUID，完成来源选择、全量/部分电池选择、划分预览与保存。
- **SC-002**: 对固定输入与随机种子，预览结果和保存后的三个分区成员完全一致。
- **SC-003**: 任何已保存逻辑数据集的父子电池关系均未跨越不同分区。
- **SC-004**: 对固定元数据样本，全体和各分区的样本数、缺失数、类别计数、数值最小/最大/平均值与独立计算的期望值一致。
- **SC-005**: 新版本写入后，旧版本的成员和统计摘要仍可完整读取。
- **SC-006**: 创建流程在无来源、无电池、请求失败、空结果和校验失败时均提供可操作的状态反馈。

## Assumptions

- 已配置并登记的数据来源代表默认开源数据集；需要先通过来源浏览器把文件登记为电池记录。
- 首版一个逻辑数据集只引用一个来源，因为当前划分和父子电池家族校验均以来源为边界。
- 一个逻辑数据集由电池成员和 train/val/test 三个分区组成，不再引入与现有版本化划分重复的独立实体。
- 统计只使用电池记录已有的元数据；未提供元数据的电池将显示为未知，不读取原始文件内容。
- 数据集差异候选选择与图表页面会在后续独立规格中接入本功能保存的摘要；本切片负责生成、持久化和读取摘要。
