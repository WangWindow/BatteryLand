# Feature Specification: 共享环境的真实训练联调

> 此共享环境方案为历史设计，已由[独立训练环境规格](../005-isolated-training-runtime/spec.md)覆盖。

**Feature Branch**: `001-backend-experiment-platform`（沿用现有未提交工作区）
**Created**: 2026-10-24
**Status**: Implemented — 共享环境、CPU/GPU、真实停止与恢复已验收，证据见quickstart.md
**Input**: 用户确认统一 Python 环境、不修改 deeplatform 或增加其依赖声明；完成 CPU 与明确 cuda:0 的真实训练、结果、停止及恢复验收。

## User Scenarios & Testing

### User Story 1 - 使用统一开发环境执行任务 (Priority: P1)

开发者只维护一个环境，平台与任务使用相同的解释器和依赖版本，避免环境选择造成调用失败。

**Why this priority**: 真实训练的前提是可复现的运行环境。
**Independent Test**: 检查平台和实际工作进程的环境身份，查询组件和执行最小任务。

**Acceptance Scenarios**:
1. **Given** 项目环境已准备，**When** 查询或启动任务，**Then** 自动使用当前环境，无需指定第二个解释器。
2. **Given** 依赖缺失或不兼容，**When** 检查能力，**Then** 返回明确原因；静态组件预览仍可用。
3. **Given** 平台正常运行，**When** 导入专业组件或执行训练，**Then** 不污染平台进程的全局注册表或日志。

### User Story 2 - 完成真实 CPU 与 GPU 电池实验 (Priority: P1)

研究人员使用现有 CALCE 数据与固定划分，完成小规模 CPU 和 GPU 实验，查询真实指标、预测和权重。

**Why this priority**: 将后端独立验收扩展为真实训练闭环。
**Independent Test**: 各执行一个单轮实验，保留可追溯的输入、设备证据和结果。

**Acceptance Scenarios**:
1. **Given** 真实示例任务，**When** 执行完成，**Then** 进程成功、日志和状态可查询；未产生结果时不虚构指标。
2. **Given** CALCE 的 9/2/2 电池划分，**When** 分别指定 cpu 和 cuda:0 执行，**Then** 真实完成训练，指标与预测可关联到原始产物。
3. **Given** 明确 GPU 请求，**When** 执行，**Then** 验证实际设备与进程归属；不可用时明确失败，不切换设备。
4. **Given** 训练框架接口不满足条件，**When** 联调，**Then** 记录具体复现与维护者反馈，不改框架核心、不替换划分或伪造成功。

### User Story 3 - 在真实训练中停止和恢复 (Priority: P2)

研究人员停止实际运行的实验，服务重启后可继续观察同一次执行，不重复启动。

**Why this priority**: 受控进程测试之外，还需核实科学运行时的生命周期。
**Independent Test**: 一个真实长实验在服务重启后保持原启动身份，停止后所属进程全部退出。

**Acceptance Scenarios**:
1. **Given** 实际训练正在运行，**When** 请求停止，**Then** 先显示停止中，确认整个进程组退出后才显示已停止。
2. **Given** 实际训练运行期间服务重启，**When** 恢复，**Then** 原始执行身份保持，启动次数不增加。

### Edge Cases

- 环境路径是符号链接，误解析到环境外解释器；已安装依赖改变现有测试的能力状态。
- GPU 在受限执行环境中不可访问；设备可用性与具体任务可运行性不同。
- 数据文件或标签缺失、样本数不足，训练或验证产物不完整。
- 子模块导入接口与依赖版本不兼容；停止发生在初始化或产物写入期间。

## Requirements

### Functional Requirements

- **FR-001**: 平台和工作进程必须共享当前运行环境，不再要求第二个解释器配置。
- **FR-002**: 所需依赖必须由主项目统一声明、解析并锁定，常规环境同步后任务依赖仍保留。
- **FR-003**: 专业模块导入与长任务必须继续在独立进程执行，避免影响平台请求处理和全局状态。
- **FR-004**: 必须以实际环境检查决定能力状态，依赖缺失时明确报告原因。
- **FR-005**: 必须验证真实最小任务以及 CALCE 单轮 CPU、cuda:0 训练，不以测试替身替代。
- **FR-006**: 必须保留指定设备并收集实际执行证据；未经证实的设备字段保持未知。
- **FR-007**: 真实实验输入、日志、指标、预测及权重必须通过现有查询接口追溯，保留单位和缺失语义。
- **FR-008**: 真实训练停止与重启必须遵守既有一次执行规则，不重复启动或提前报告退出。
- **FR-009**: 不得修改训练子模块或增加其依赖声明；发现框架问题必须形成可复现反馈。
- **FR-010**: 原有后端行为与公共接口必须回归验证，既有验收记录不得改写为本次真实训练证据。

### Key Entities

- **运行环境身份**：当前解释器、环境前缀、依赖版本及 GPU 运行时信息。
- **真实验收实验**：固定数据、配置、执行身份、原始产物和验收结论。
- **对接问题记录**：失败阶段、复现步骤、证据和责任边界。

## Success Criteria

- **SC-001**: 平台与实际工作进程的环境身份一致，常规启动无需配置第二个环境。
- **SC-002**: 一个示例任务、一个 CPU 电池实验、一个指定 GPU 电池实验完成真实验收；任何受阻项分别标明原因。
- **SC-003**: 所有验收产物可从实验查询追溯，指标与原始结果一致。
- **SC-004**: 真实停止/重启验收不发生第二次启动，停止终态对应所属进程组退出。
- **SC-005**: 原有后端验收继续通过，训练子模块内容和提交保持不变。

## Assumptions

- 使用既有 CALCE 划分的 13 个文件；不裁剪或变造内置划分。
- 执行设备固定 cpu 与 cuda:0，先 CPU 后 GPU；不支持 auto、多卡并行或独立评估/迁移。
- 本轮不构建前端、增加公共接口或改变数据库结构。
- 若训练侧缺口阻止验收，先完成宿主侧可验证工作，再明确交付复现和未完成项。
