# 后端服务拆分与完整实验数据流

## 范围和所有权

本阶段先稳定后端 HTTP 契约和消费者数据流，再开发前端。三个独立进程分别为数据后端、
调度器和 DeepPlatform HTTP 适配服务。数据后端独占 SQLite；调度器只经 HTTP
认领和更新实验，负责 FIFO 串行调度及 CPU、内存、GPU 资源监测；训练适配服务独占
DeepPlatform 校验、准备、启动、状态、停止和输出提取。三者可以部署在同一主机。

用户侧构建或上传完整 YAML 配置及完整划分 JSON，先向训练适配服务校验，再将原文、
解析结果、哈希和可信校验收据提交数据后端。数据后端只保存通过校验的版本，不拼装配置、
不自行执行数据划分算法。原始输入与运行时设备解析结果分别保存。历史记录缺失原文时
明确标记为旧版结构化文档，不伪称重新导出的 YAML 为原文。

每个实验 ID 在整个生命周期只对应一次训练。首次排队冻结输入；再次训练同一配置须
创建新实验 ID 和新运行目录。停止、失败和完成状态不得重新入队。重复 HTTP 请求只能
返回此前收据。进程身份无法确认时进入 `needs_reconciliation`，不得自动再次启动。
不提供断点续训。首版调度全局 FIFO 串行。仅支持 GPU：`auto` 在派发前解析成具体
`cuda:N`，显式 `cuda:N` 必须保留，无可用 GPU 时任务留在队列并报告原因。

固定数据根目录在启动时建立 SQLite 文件目录索引，支持分页、筛选、集合成员查询。
命名划分文件作为选择捷径；最终划分 JSON 来自客户端并经提供者校验，数据库保存其
原文、成员索引和统计摘要。真实文件不上传也不复制。结果、指标、日志和产物以实验 ID
关联，并可经公开 API 查询。大文件存文件系统，数据库保存元数据与校验哈希。

## 验收条件

1. 三个进程可独立启动；调度与训练服务无需导入数据后端 ORM，浏览器无需服务密钥。
2. 原文哈希、提供者提交和组件版本纳入校验收据；过期、篡改、未校验内容拒绝保存。
3. 两个调度器并发认领时，最多一个任务占用串行容量；断线重传不会二次启动。
4. 资源快照有采样时间和缺失原因；`auto` 只解析到实际可用 GPU，显式卡不重映射。
5. 停止命令、终态上报、指标与产物重传具有确定语义，实验 ID 可追踪完整数据。
6. 独立 HTTP 客户端完成创建、校验、保存、排队、认领、运行、停止/完成及结果查询。
7. 至少三次独立清空业务库后的完整流回归通过，随后才进入前端实现。

## 已知外部依赖

当前 DeepPlatform 的 BatteryLifeDatasetFactory 只读取内置划分目录，尚不能消费每个实验
的自定义划分 JSON。需由其维护者增加可选 `datafactory.params.split_file` 等等效接口；
主项目只记录本地接口请求，不修改子模块源码。交付前不得将自定义子集真实训练标为通过。
独立评估和迁移任务也需提供者另行声明能力。
