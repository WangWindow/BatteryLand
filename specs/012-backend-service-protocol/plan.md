# 实施计划

## Constitution Check

保持前后端分离；数据后端独占 SQLite 和 SQLAlchemy ORM；专业逻辑留在 DeepPlatform；
三个进程通过带版本的 HTTP DTO 通信。各服务内部保持领域、应用、基础设施、接口分层。
不引入 Redis、MongoDB、消息队列或 CPU 训练路径。使用 TDD，从契约失败测试开始；
端到端用独立进程和公开 HTTP，不能用测试容器内部对象代替。

## 顺序

1. 修复测试收集和陈旧断言，建立 114 项基线。
2. 建立可信原始文档校验与保存、固定文件目录索引和按实验查询接口，增量迁移旧库。
3. 建立 DeepPlatform HTTP 适配服务，搬出训练进程所有权。
4. 建立独立调度器及资源监测，数据后端提供原子认领、执行事件和结果写入接口。
5. 删除数据后端进程内调度循环、进程控制和结果目录扫描；更新项目相对路径启动脚本。
6. 用真实独立进程和标准 HTTP 客户端进行并发、重传、停机和 GPU 完整流测试。

每段独立检查并按职责提交。仅在检查通过、功能独立可用时合入主分支。
