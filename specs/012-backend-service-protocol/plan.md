# 实施计划

## Constitution Check

保持前后端分离；单个 FastAPI 后端独占 SQLite 和 SQLAlchemy ORM，内置调度模块；
专业逻辑留在 DeepPlatform，通过隔离解释器的子进程运行。前后端通过版本化 HTTP DTO 通信。
不引入 Redis、MongoDB、消息队列或 CPU 训练路径。使用 TDD，从契约失败测试开始；
端到端用独立进程和公开 HTTP，不能用测试容器内部对象代替。

## 顺序

1. 修复测试收集和陈旧断言，建立 114 项基线。
2. 建立可信原始文档校验与保存、固定文件目录索引和按实验查询接口，增量迁移旧库。
3. 建立 DeepPlatform 适配器的校验及一次性启动契约，训练由隔离解释器执行。
4. 建立后端内部调度器及资源监测，数据层提供原子认领、执行事件和结果写入事务。
5. 单端口运行 FastAPI，前端使用开发代理；更新项目相对路径启动脚本。
6. 用单后端 HTTP 客户端及真实训练子进程进行并发、重传、停止和 GPU 完整流测试。

每段独立检查并按职责提交。仅在检查通过、功能独立可用时合入主分支。
