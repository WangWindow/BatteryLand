# Feature Specification: 模块化实验工作台闭环

**Feature Branch**: `003-modular-workflow`
**Created**: 2026-10-24
**Status**: Ready for planning
**Input**: 两个既有引擎提供数据和训练支持；独立调度模块经公开接口请求执行，交付可替换的简版前端与浏览器交互图表，以实际使用发现并补齐后端接口缺口。

## User Scenarios & Testing

### User Story 1 - 准备资源与划分 (Priority: P1)

研究人员在网页登记允许的数据来源、导入清单，检索电池，管理版本化划分。

**Why this priority**: 实验必须引用可追溯的真实资源。
**Independent Test**: 在空平台登记来源并导入清单，筛选电池，创建/修改/导入/导出划分。

**Acceptance Scenarios**:
1. **Given** 允许的数据来源，**When** 重复导入同一清单，**Then** 不产生重复电池，网页显示新增与已存在数量。
2. **Given** 检索结果，**When** 创建或修改划分，**Then** 版本及成员可查询，重叠或修订冲突有明确错误。
3. **Given** 已有划分，**When** 下载并重新导入，**Then** 保留相同电池分组语义。

### User Story 2 - 配置和校验实验 (Priority: P1)

研究人员浏览组件与参数，上传组件或权重，导入和维护模板，再创建、编辑、校验及复制实验。

**Why this priority**: 让真实执行输入可在网页完成准备。
**Independent Test**: 从模板创建草稿、修改输入、查看校验，修改模板后旧草稿不变。

**Acceptance Scenarios**:
1. **Given** 组件目录，**When** 查看参数或上传组件，**Then** 显示真实返回内容及可用性，缺依赖不伪装成功。
2. **Given** 模板及划分，**When** 创建草稿并校验，**Then** 保存与执行校验分离，错误定位到相关输入。
3. **Given** 终态实验，**When** 复制，**Then** 产生独立草稿；旧执行和结果保持不变。

### User Story 3 - 使用独立调度器执行和停止 (Priority: P1)

调度模块独立运行和替换，选择队列任务；平台引擎统一保存状态及控制训练进程。

**Why this priority**: 策略演进不应要求重写数据服务或训练引擎。
**Independent Test**: 仅通过公开接口启动两个排队任务，核验串行、重复派发、停止与重启。

**Acceptance Scenarios**:
1. **Given** 多个排队实验，**When** 默认调度器运行，**Then** 按入队顺序串行执行，明确设备原样传递。
2. **Given** 同一任务的重复或并发派发请求，**When** 引擎处理，**Then** 至多启动一次，不绕过执行容量或待核实状态。
3. **Given** 调度器离线，**When** 已有实验运行或被停止，**Then** 引擎继续观察、停止及采集，排队任务等待调度器恢复。
4. **Given** 引擎或调度器重启，**When** 恢复，**Then** 保持原执行身份，不重跑已认领实验。

### User Story 4 - 观察执行和结果 (Priority: P1)

研究人员查看执行状态、持续日志、指标、预测和产物并下载权重。

**Why this priority**: 执行进度与结果必须可实际追溯。
**Independent Test**: 网页观察一个真实任务，从日志进入指标、预测及产物；刷新页面保持一致。

**Acceptance Scenarios**:
1. **Given** 运行任务，**When** 打开详情，**Then** 日志增量更新，断线可恢复，终态后读尽剩余日志。
2. **Given** 完成或失败的任务，**When** 查看详情，**Then** 执行状态、采集状态和失败原因分别表达。
3. **Given** 已登记产物，**When** 下载，**Then** 获取对应文件，网页不需要服务器物理路径。

### User Story 5 - 浏览器比较与交互图表 (Priority: P2)

研究人员比较实验指标、轮次曲线、预测与真值，以及电池集合数量、分类和重叠。

**Why this priority**: 通过实际展示检验后端数据与缺失值语义。
**Independent Test**: 比较指标不同、名单不同、缺少真值的结果，交互图表与原数据一致。

**Acceptance Scenarios**:
1. **Given** 多个实验，**When** 选择指标或图型，**Then** 在浏览器绘图，图例、单位和来源清晰，缺失数据不补零。
2. **Given** 不兼容单位或粒度，**When** 比较，**Then** 分开显示并解释原因；没有真值时不绘制伪造散点。
3. **Given** 集合或图表尚未打开，**When** 首次进入相关视图，**Then** 按需加载；大列表分页，采样明确注明。

### User Story 6 - 可替换模块与准确能力说明 (Priority: P2)

维护者通过稳定边界替换调度策略或图表组件，查看完整性矩阵及真实限制。

**Why this priority**: 简版实现服务于完整流程及后续协作。
**Independent Test**: 测试中替换调度策略和图表数据输入，不修改存储或训练核心。

**Acceptance Scenarios**:
1. **Given** 兼容的调度实现，**When** 更换模块入口，**Then** 只需公开接口与配置，无需访问引擎内部类或数据库。
2. **Given** 尚不支持的自定义划分、评估、迁移或设备，**When** 操作，**Then** 显示明确限制，不使用模拟结果冒充真实完成。

### Edge Cases

- 旧版本编辑、资源受引用、重复导入、组件缺依赖、上传失败或文件过大。
- 派发响应丢失、重复请求、两个调度器竞争、停止与准备并发、进程身份不确定。
- 日志游标失效、请求中途换页、组件卸载、图表空数据和未知自定义指标。
- provider 原始数据缺失、自定义划分入口未交付、非默认 CUDA 编号不满足前置条件。

## Requirements

### Functional Requirements

- **FR-001**: 用户必须能从网页完成资源、划分、模板和实验的现有管理操作及导入导出。
- **FR-002**: 用户必须能浏览组件、查看参数及上传组件和权重，得到真实能力或错误说明。
- **FR-003**: 草稿必须支持完整输入编辑、版本绑定、校验、复制，入队后冻结输入。
- **FR-004**: 调度模块必须独立启动，仅通过公开接口查询队列和请求派发，不操作引擎数据文件或训练进程。
- **FR-005**: 默认策略必须为可替换的 FIFO 串行策略；策略选择与引擎执行机制分离。
- **FR-006**: 派发必须原子认领；同一执行的重复请求不得启动第二个进程，并发请求不得突破串行容量。
- **FR-007**: 引擎必须在没有调度模块时继续执行观察、停止和采集；重启不得自动重新执行已认领任务。
- **FR-008**: 设备必须明确指定，原样传递；首期拒绝 auto，不增加多卡并行。
- **FR-009**: 用户必须能查看队列、取消排队或停止运行，区分停止受理和实际退出。
- **FR-010**: 日志必须增量读取，支持恢复或明确游标重置提示；不得重复全量拉取。
- **FR-011**: 结果展示必须保留来源、缺失值、自定义指标、单位及粒度语义，支持受控产物下载。
- **FR-012**: 图表必须由浏览器实际渲染及交互，覆盖六种现有图型，不以静态图片替代。
- **FR-013**: 页面与可视化模块必须分离，独立替换绘图组件不改变页面业务或持久化协议。
- **FR-014**: 页面必须具有一致的主题、表单、分页、键盘标签及加载、空、错误和禁用状态。
- **FR-015**: 非图表页面不得加载绘图库；列表分页，日志增量读取，大图表限制可见数据并说明采样。
- **FR-016**: 所有模块必须使用公开后端接口；接口缺口须补充契约和行为测试，保留现有兼容接口。
- **FR-017**: 必须提供需求覆盖矩阵，区分既有交付、本轮缺口及后续原始需求，不将测试替身标为生产能力。
- **FR-018**: 首期必须完成真实浏览器、独立调度器、后端引擎及训练引擎的验收闭环。

### Key Entities

- **任务派发请求**：排队实验身份、预期修订与调度策略标识；对应同一个既有启动意图。
- **工作台状态**：查询条件、选中资源、图型及临时编辑内容；权威业务状态仍由引擎保存。
- **图表输入**：声明式图表、来源、单位、粒度和缺失值；不含可执行代码或文件系统路径。
- **覆盖矩阵**：需求、现有契约、证据、缺口及责任模块之间的对应关系。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 六个用户故事均具有自动化行为证据；网页能完成资源准备到结果比较的完整主流程。
- **SC-002**: 两个任务串行完成；同一任务重复派发十次仍只有一次启动，两个竞争调度器不能产生并行训练。
- **SC-003**: 调度器离线及恢复、引擎重启、训练停止三个场景保持执行身份与持久化状态一致。
- **SC-004**: 六种图型可在浏览器验证；自定义指标、不同名单、缺失真值及单位不兼容均准确展示。
- **SC-005**: 首次打开非图表页面不请求绘图库资源；分页列表每页最多200项，日志单次不超过64KiB。
- **SC-006**: 覆盖矩阵中每项原始需求均有明确归属和状态；不宣称未交付的专业能力已完成。

## Assumptions

- 技术与目录基线遵循宪章2.2.0；前端先保持一个应用，在应用内部隔离可视化模块。
- 使用现有训练、基础集合差异与六种声明式图表；不增加独立评估、迁移、退化信号分析、数据质量治理、不确定性或模型导出。
- 不改 deeplatform；真实电池训练使用已验收的 CALCE 原生划分，其他划分可管理和导出但不保证 provider 可执行。
- 本地单后端运行根、同一Python环境，无新增Redis、消息队列或外部数据库服务。
