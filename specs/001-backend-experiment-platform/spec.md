# Feature Specification: 电池实验平台后端首版业务

**Feature Branch**: `001-backend-experiment-platform`

**Created**: 2026-10-23

**Status**: Implemented — 七个后端故事已实施验证；真实训练环境与 provider 对接限制见 quickstart.md

**Input**: User description: "为可信团队建立以持久化和高效查询为中心的实验后端。管理已有电池资源、划分、配置、模板和单次实验，接入 deeplatform；先提供可替换的串行调度、基础差异分析及声明式图表能力。明确设备，暂不支持 auto；训练框架问题反馈维护者。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 导入并检索已有电池资源 (Priority: P1)

研究人员登记已有标准化数据源及电池清单，通过名称、来源和已登记的分类信息检索资源，
了解平台可用于实验的数据，不必逐一打开原始文件。

**Why this priority**: 明确资源身份与来源是划分、实验和结果关联的基础。

**Independent Test**: 用固定资源清单完成导入、重复导入、筛选和详情查询，无需训练环境。

**Acceptance Scenarios**:

1. **Given** 一个已允许的数据源及包含重复引用的清单，**When** 导入两次，**Then** 同一来源的同一电池只登记一次，返回新增及已存在数量。
2. **Given** 两个来源包含同名文件，**When** 查询资源，**Then** 两个资源有不同身份，来源可区分。
3. **Given** 资源具有不同分类字段及缺失字段，**When** 按已有分类筛选并分页，**Then** 返回符合条件的资源及准确总数，缺失字段不被猜测补齐。
4. **Given** 数据文件当前不可访问，**When** 查询已登记资源，**Then** 保留资源记录并说明可用性，不将存在文件引用视为已经确认数据可读。

---

### User Story 2 - 创建可复现的数据划分 (Priority: P1)

研究人员选择电池，手动指定、按比例随机或固定部分后随机分配训练、验证、测试集合，
保存命名划分并查看成员与基础分布。

**Why this priority**: 划分必须可复用、可追溯，避免训练和评估数据泄漏。

**Independent Test**: 使用固定电池资源完成三种划分方式、版本修改和导出，无需执行实验。

**Acceptance Scenarios**:

1. **Given** 固定资源集合、比例与随机种子，**When** 重复生成划分，**Then** 成员和顺序相同；混合划分保留手动成员，仅对剩余电池随机分配。
2. **Given** 一个电池及其派生样本，**When** 将其放入不同分组或重复加入同一分组，**Then** 拒绝保存并指出冲突成员。
3. **Given** 已被实验引用的划分，**When** 修改或删除，**Then** 修改产生新版本且原版本保留，受引用资源不能直接删除。
4. **Given** 已保存划分，**When** 导出训练使用的成员清单，**Then** 导出内容与指定版本一致，包含三个分组；空分组被明确保留，能否执行由对应任务的要求决定。

---

### User Story 3 - 管理实验配置、模板与草稿 (Priority: P1)

研究人员导入现有配置或选择模板，填写实验参数与资源引用，保存草稿、校验并导出配置。
预训练、评估和迁移实验通过任务能力区分，尚未提供的执行能力有明确说明。

**Why this priority**: 配置及其引用必须先可靠保存，才能成为执行和查询的依据。

**Independent Test**: 使用固定模板及可控校验能力完成导入、编辑、校验和复制，无需真实训练。

**Acceptance Scenarios**:

1. **Given** 合法模板，**When** 创建并修改实验草稿，**Then** 参数和引用持久保存，模板保持原版本；草稿可按需保存为新模板。
2. **Given** 不合法的参数、失效引用或不支持的任务，**When** 校验，**Then** 返回对应位置与原因，不创建训练进程。
3. **Given** 设备为 `auto`，**When** 执行校验或提交执行，**Then** 明确拒绝；明确指定的设备不得被改写或静默替换。
4. **Given** 修改过模板或划分，**When** 查看已提交实验，**Then** 仍看到该实验冻结的原始输入及版本。
5. **Given** 文档发布或关联保存失败，**When** 再次查询，**Then** 原有有效版本仍可用，新半成品不会被报告为保存成功。

---

### User Story 4 - 串行执行、停止和复制实验 (Priority: P1)

研究人员按顺序提交实验，查看排队和执行情况，取消排队项或停止正在执行的实验。
每个实验仅执行一次，重跑时复制为新实验。

**Why this priority**: 首版需要真实、受控且可追溯的执行闭环。

**Independent Test**: 使用受控短任务验证队列和生命周期，再对已就绪训练能力进行独立联调。

**Acceptance Scenarios**:

1. **Given** 多个合法草稿，**When** 按指定顺序提交，**Then** 固定各自输入并依次执行，同一时间最多一个受管理实验处于启动或执行过程。
2. **Given** 已排队、正在启动或运行的实验，**When** 再次提交同一实验，**Then** 返回现有执行状态而不产生第二次执行；终态实验必须复制后才能再次执行。
3. **Given** 排队项或运行项，**When** 请求停止，**Then** 排队项直接取消；运行项先进入停止中，确认所属执行进程退出后才成为已停止。
4. **Given** 服务重启或启动结果不确定，**When** 恢复，**Then** 先核对执行身份；不自动重跑，无法确认时标记待核实并暂停新增派发。
5. **Given** 复制一个已完成实验，**When** 创建新实验，**Then** 生成新身份，复制可编辑输入，不复制执行状态、日志或结果。

---

### User Story 5 - 查询并接入训练组件与权重 (Priority: P2)

研究人员查询可用组件及配置参数，上传可信组件，登记和选择权重，为后续实验准备资源。

**Why this priority**: 扩展能力必须遵循训练框架实际接口，减少配置错误及重复维护。

**Independent Test**: 通过固定组件目录和训练工具联调验证查询、上传及权重引用，不执行完整训练。

**Acceptance Scenarios**:

1. **Given** 组件具有必填参数、默认值和框架注入参数，**When** 查询描述，**Then** 准确区分可填写字段、默认值、不可配置项与诊断信息，不凭示例推测默认值。
2. **Given** 不合法源码、重名组件或越界文件名，**When** 上传，**Then** 拒绝安装且不执行源码；新合法组件在后续实验中可发现。
3. **Given** 一个权重资源，**When** 登记或选择，**Then** 可以查询其来源实验、组件关联和可用性；登记成功不等同于训练任务已支持加载该权重。

---

### User Story 6 - 监控实验并查询结果产物 (Priority: P2)

研究人员查看实验状态、增量日志和轮次指标，检索最终指标、逐电池预测及权重产物。

**Why this priority**: 用户需要知道实验是否执行、为何失败以及结果来自哪些输入。

**Independent Test**: 导入包含部分日志、完整结果及缺失可选产物的固定样例，验证监控与查询。

**Acceptance Scenarios**:

1. **Given** 日志和指标正在写入，**When** 增量获取，**Then** 已完成内容有连续位置，尚未写完的记录等待后续读取，不重复导入指标。
2. **Given** 训练失败或某类任务没有指标文件，**When** 查询，**Then** 分别展示失败原因或该产物不可用，不伪造指标，也不因可选产物缺失一律判任务失败。
3. **Given** 窗口级指标和逐电池平均预测，**When** 导入及查询，**Then** 保留各自聚合粒度、单位和来源，不用后者重算覆盖前者。
4. **Given** 结果重新采集或文件发生替换，**When** 导入，**Then** 不产生重复记录，查询结果关联明确版本；损坏结果有可定位错误。

---

### User Story 7 - 比较电池集合与实验结果 (Priority: P2)

研究人员比较电池集合规模、重叠及已登记类别分布，比较多个实验的指标和预测，
获取可在浏览器中交互展示的图表数据和声明描述。

**Why this priority**: 提供可验证的基础洞察，并为未来专业分析和绘图模块保留替换边界。

**Independent Test**: 使用固定集合和两个字段不完全相同的实验结果，验证比较、导出及基础图表描述。

**Acceptance Scenarios**:

1. **Given** 多个电池集合，**When** 选择基础差异分析，**Then** 返回真实成员数量、交集差集或已有类别分布，标明缺失元数据。
2. **Given** 实验指标和电池名单不同，且存在自定义指标 `ABC`，**When** 比较，**Then** 保留指标与电池并集，明确缺失项，不补零、不混淆资源身份。
3. **Given** 可用轮次指标或最终指标，**When** 请求基础折线图或柱图，**Then** 返回真实序列、坐标和单位；无真实值时，依赖真实值的散点图明确不可用。
4. **Given** 尚未支持的分析、图类型或不一致的比较单位，**When** 请求比较或绘图，**Then** 返回明确原因，不生成模拟结果或误导性合并。
5. **Given** 已完成比较，**When** 导出结构化数据，**Then** 保留实验、电池、指标身份、单位及缺失语义，不把空值转换为零。

### Edge Cases

- 同名资源来自不同来源；同一电池出现在多个命名划分中；派生样本跨分组泄漏。
- 随机比例、固定成员和剩余成员不相容；空分组合法但对应训练任务无法使用。
- 配置引用不存在、组件重名、任务不支持、设备不可用、`auto` 未支持。
- 多个调用方同时修改同一草稿或提交同一实验；批量提交中存在不合法项。
- 文档已发布而关联保存失败；文档损坏、产物缺失、磁盘写入失败及跨版本引用错误。
- 训练进程启动后回执丢失，进程号被复用，状态文件仍显示运行但进程已经退出。
- 停止与自然完成同时发生，强制终止前最后一条指标或权重未完成写入。
- 增量文件尾部半条记录、文件截断或替换；相同结果重复采集。
- 指标缺失、真实值缺失、不同电池集合、自定义指标、单位或聚合粒度不一致。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须登记已有标准化数据来源、电池身份及可用元数据，区分同名但来源不同的电池。
- **FR-002**: 相同来源清单的重复导入必须幂等，并报告新增、已存在和错误记录；不得静默覆盖相互矛盾的身份信息。
- **FR-003**: 系统必须按名称、来源及已登记分类检索电池资源，提供准确总数、稳定排序和分页。
- **FR-004**: 系统必须明确区分资源已登记与数据文件实际可用；不得猜测缺失的化学体系、温度或单位。
- **FR-005**: 系统必须保存命名划分，支持手动、随机及混合划分；相同有序输入、种子和参数必须得到相同划分。
- **FR-006**: 划分必须拒绝不存在的资源、分组内重复及跨分组重叠；同一电池的派生样本必须作为同一分配单元。
- **FR-007**: 划分修改必须生成可引用版本，支持成员查询及训练所需清单导出；受引用版本不能删除。
- **FR-008**: 系统必须支持配置和模板的创建、查询、草稿修改、复制、导入及导出，并保留引用关系。
- **FR-009**: 实验必须关联配置、划分版本、任务、组件及必要权重；迁移实验需表达源域、目标域及预训练权重。
- **FR-010**: 校验必须区分平台资源约束、训练配置约束和能力未就绪，并返回可定位的原因；校验不得启动训练。
- **FR-011**: 首版执行必须使用明确设备，拒绝 `auto`；不可用设备不得被静默改成其他设备。
- **FR-012**: 首次提交执行被接受后必须冻结输入版本及组件、框架身份；一个实验只允许一次执行。
- **FR-013**: 重复提交活动实验必须复用既有状态，终态实验再次执行必须复制为新实验且不复用旧产物。
- **FR-014**: 系统必须持久保存队列顺序，按提交顺序串行执行；批量提交存在不合法项时不得部分接收新实验。
- **FR-015**: 运行前必须从已保存快照生成可追溯的训练输入，并记录输入与产物的关联；不得以可变模板替代冻结快照。
- **FR-016**: 系统必须区分草稿、排队、启动中、运行中、停止中、成功、失败、取消、已停止及待核实状态。
- **FR-017**: 系统必须支持取消排队项和终止正在执行的实验；确认实际退出前不得报告已停止。
- **FR-018**: 重启或启动结果不确定时必须核对执行身份，不自动重跑；待核实活动实验存在时暂停新增派发。
- **FR-019**: 系统必须保护活动实验和受引用资源不被直接删除；允许删除未受引用草稿及明确可删除的终态记录。
- **FR-020**: 系统必须复用训练框架的组件目录、参数描述及上传能力，区分必填、默认、注入和不可配置参数。
- **FR-021**: 组件上传必须拒绝非法、重名及越界内容，校验与安装不得执行上传源码，不覆盖已有组件。
- **FR-022**: 系统必须登记权重来源、组件关联与可用性，并允许查询和受控下载；实际加载能力由任务声明。
- **FR-023**: 系统必须提供带连续位置的增量日志和轮次指标读取；只导入完整记录，重复采集不得重复产生查询结果。
- **FR-024**: 系统必须保留最终指标、逐电池预测、最佳轮次及产物引用，明确可选产物缺失和读取错误。
- **FR-025**: 结果必须保留指标名称、单位、聚合粒度及来源；请求设备不能冒充已验证的实际设备。
- **FR-026**: 常用实验检索必须覆盖数据集、模型、任务、状态、请求设备、时间及源域/目标域；完整配置按需读取。
- **FR-027**: 系统必须提供基于真实集合的规模、重叠和已有类别分布分析，明确未支持的专业分析。
- **FR-028**: 实验比较必须容纳指标并集、电池并集、自定义指标及缺失真实值，不补零或混合不相容单位与粒度。
- **FR-029**: 系统必须返回基础柱图、折线图及真值预测散点所需的数据和声明描述，标注坐标、单位、序列身份和缺失信息。
- **FR-030**: 系统必须支持导出配置、划分和结构化比较结果，并受控提供产物下载；浏览器图表交互由前端承担。
- **FR-031**: 业务数据保存失败必须保持原有可查询版本有效；不得出现被报告为可用的半成品资源。
- **FR-032**: 常用检索不得通过每次扫描全部配置、结果或实验目录实现；查询摘要必须与其来源版本一致。
- **FR-033**: 系统必须声明当前支持的执行、调度、分析和图表能力；基础实现使用真实输入，未接入能力明确不可用。
- **FR-034**: 训练框架缺口必须记录为对接条件；不得静默换用其他划分、修改子模块核心或伪造执行结果。

### Key Entities *(include if feature involves data)*

- **数据来源与电池资源**：来源、稳定身份、名称、文件引用、已知元数据及可用性；来源与文件名共同区分资源。
- **数据划分及版本**：命名集合、版本、三个分组成员、生成方式与种子；版本可被实验固定引用。
- **配置模板及版本**：可复用配置、描述、任务及组件引用；修改不影响已有实验。
- **实验**：稳定身份、草稿或冻结配置、数据与组件版本、明确设备、队列和单次执行状态、时间及结果引用。
- **组件资源**：注册域、类型、参数描述、来源及源码身份；与训练框架实际目录对应。
- **权重与其他产物**：类别、来源实验、组件关联、文件引用、内容身份及可用性。
- **实验结果**：版本、最佳轮次、指标、逐电池预测、真实值及各自单位和聚合语义。
- **比较数据与图表描述**：按实验和电池身份对齐的数据、缺失标记、坐标、序列及展示说明；默认按请求生成。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 固定验收样例中，导入同一资源清单两次后，电池数量保持不变；23 份划分的 2,160 条成员引用能够关联到 1,001 个不同文件引用，不因集合重叠重复登记。
- **SC-002**: 在单用户、1,001 条电池记录、23 份划分及 100 条实验记录的本地验收基准下，至少 95% 的常用资源及实验检索在 2 秒内返回；不包含训练、专业分析和大文件传输。
- **SC-003**: 相同种子划分可重复得到完全相同结果，全部重叠、重复及失效资源样例均被拒绝。
- **SC-004**: 连续提交三个合法实验时最多一个同时执行；对同一实验重复提交十次仍只产生一次执行。
- **SC-005**: 修改模板、划分或复制实验后，既有实验的冻结输入和结果均保持不变；重启和不确定启动样例均不引发自动重跑。
- **SC-006**: 验收样例中的停止受理、停止中和真正退出可区分，未确认退出不会显示为已停止。
- **SC-007**: 含自定义指标、缺失指标、缺失真实值和不同电池名单的全部比较样例保留原始含义，不出现补零、虚构值或错误单位转换。
- **SC-008**: 仅凭资源、实验和结果查询即可追溯每个固定验收结果的配置、划分、组件及来源产物；全部主要用户故事有可重复的成功与失败验收场景。
