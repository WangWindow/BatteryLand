# Feature Specification: 数据来源浏览与电池导入

**Feature Branch**: `010-data-source-browser`
**Created**: 2026-10-24
**Status**: Complete

用户需要看清数据集来自哪个本地数据目录，并能在界面中浏览已配置目录里的电池文件，选择后登记到平台数据库。浏览器和 API 不接收或暴露任意服务器绝对路径。

## User Stories

### US1 — 看懂已登记数据集的来源 (P1)

用户在数据页面看到已登记数据集、数据目录标识和目录可用状态，能够打开某个来源并查看其已登记电池。

**独立验收**：数据来源是页面主要内容，不藏在折叠区；列表能区分“数据集名称”和“服务端目录别名”，并能按来源筛选电池。

### US2 — 从已配置目录选择电池文件 (P1)

用户选择已有数据集后，可搜索、分页浏览其受控目录中的 `.pkl` 文件，勾选多个文件并一次性导入登记。

**独立验收**：新文件以安全的相对引用进入数据库；导入报告区分新增和已存在文件；重复导入幂等；数据库只记录目录根内可访问的文件。

### US3 — 注册新的服务端数据目录 (P1)

用户把已由运行环境配置的目录别名登记为有名称的数据集，并查看该目录是否可用及可导入的文件数量。

**独立验收**：选择器显示目录名、别名、可用状态及文件数量；页面以短提示说明目录由后端 `BATTERYLAND_SOURCE_ROOTS` 提供；不要求用户在表单里填写服务器路径。

## Requirements

- **FR-001**: 数据来源卡片展示数据集名称、后端目录名/别名、可用状态和可导入文件数；卡片可以筛选下方已登记电池。
- **FR-002**: 新建数据来源只接受后端配置的 root alias；界面以可读目录名和计数展示选项，并保留 alias 作为稳定存储标识。
- **FR-003**: 来源详情支持对配置根目录内的 `.pkl` 文件进行搜索和分页；响应只包含文件名、相对键、大小和可导入状态，不返回绝对路径或文件内容。
- **FR-004**: 文件扫描不得跟随符号链接、不得越出配置根；忽略隐藏项和不支持扩展名；重名文件不得造成错误登记。
- **FR-005**: 用户可以勾选当前或多个分页中的文件并批量登记；已有文件可重试且不会复制；未勾选时禁止提交。
- **FR-006**: 文件夹扫描是发现操作，不读取 pickle 内容；电池元数据保持未知，仍可通过现有元数据清单导入能力补充。
- **FR-007**: 现有 API schema 的错误包装、分页约定和来源/电池身份保持兼容；后端使用既有 ORM 与 unit-of-work 边界。
- **FR-008**: 中英文文案一致，界面采用克制的卡片与单一主操作；高级 JSON 清单导入保留为次级入口。

## Assumptions

- 浏览器不能安全地浏览服务器文件系统；本项目只允许浏览 `BATTERYLAND_SOURCE_ROOTS` 明确配置的后端目录。
- 每个注册数据来源代表一个配置 root alias；扫描直接子目录和其下一层 `.pkl` 文件，与现有打包数据扫描规则一致。
- 数据文件按源内 basename 唯一；发生同名冲突的候选文件标记为不可导入，并由用户调整目录组织后重试。
- 导入只登记数据文件引用，不复制大型电池文件；实验仍由 Deeplatform 从配置目录读取原始文件。

## Success Criteria

- **SC-001**: 用户能在不输入路径或编写 JSON 的情况下注册已配置目录、浏览文件并登记所选电池。
- **SC-002**: 目录不可用、路径穿越、符号链接和同名候选不会泄露路径或产生错误引用。
- **SC-003**: 同一文件重复导入不增加记录；跨来源同名文件仍保持独立身份。
- **SC-004**: 页面显示每个数据集的来源信息和文件计数，并能从来源卡片筛选对应电池。
